# Hallazgos de ejecución y límites observados

1. **Arranque nativo:** el contenedor Python slim no tenía `libexpat.so.1`, requerida por Rasterio. La receta instala `libexpat1`; no se sustituyó el motor.
2. **Plantillas de recursos:** las expresiones `{?limit,...}` upstream registraban pero provocaban un error regex al resolver recursos con FastMCP 2.12.3. La compatibilidad conserva parámetros de ruta y defaults; no se anuncian esas opciones de query como admitidas.
3. **Catálogo:** tres recursos enviaban `limit` a una función que no lo aceptaba y llamaban `.to_dict()` a un modelo Pydantic sin ese método. Se admiten límite/subdirectorio y se serializa con `.model_dump()`. El subdirectorio se confina al workspace.
4. **COG:** reabrir en `r+` para crear overviews después de cerrar el escritor fallaba y podía romper el layout optimizado. Se construyen antes de cerrar; se verifica `LAYOUT=COG`, niveles y píxeles. No se usa `IGNORE_COG_LAYOUT_BREAK` para ocultar el problema.
5. **Justificación:** el schema upstream declaraba un diccionario genérico aunque validaba una estructura anidada. Codex necesitó corregir dos intentos. Se expone el modelo `Justification` existente en la anotación, conservando validación/lógica.
6. **Host Codex:** `auto` combinado con política CLI `never` bloqueaba incluso lectura. El benchmark autoriza únicamente el servidor del caso con su configuración soportada `default_tools_approval_mode="approve"`; mantiene shell de solo lectura y verifica que no se haya usado. No es un rechazo de revisión científica del MCP.
7. **Diferencias entre hosts:** Codex no exponía el prompt requerido por el preflight. Usó la herramienta de justificación; Hermes sí accedió a prompts/recursos. El servidor mantiene recursos, prompts, esquemas y guía del caso para soportar ambos recorridos.
8. **Afirmación del agente:** el primer Hermes convirtió una diferencia de población tabular en una afirmación sobre residentes fuera de polígonos. El contrato ahora declara expresamente que no hay coordenadas de residentes. El primer ensayo se conserva como hallazgo y se repite la tarea; no se cambia el resultado esperado para esconderlo.
9. **Infraestructura local:** Docker no pudo crear otra red porque los pools locales estaban agotados. La receta utiliza el bridge existente para adquisición/MCP y `network_mode: none` para análisis; no se borraron redes ajenas. En mounts Windows, el usuario del contenedor no podía aplicar `chmod`; los JSON se crean con modo declarado y reemplazo atómico, sin cambiar permisos del host.
10. **Disponibilidad de datos:** el WFS municipal `kartta.hel.fi` tuvo timeout; HRI API devolvió 403 en este entorno. La receta ejecutada usa Service Map y PxWeb que sí respondieron. Se consultó también WFS de Statistics Finland/HSY. El snapshot público fijado permite repetir sin disponibilidad del portal de descubrimiento.

No se ha probado toda variante de formato/driver, uso multiusuario concurrente del mismo workspace, todos los clientes MCP o arquitecturas distintas de Linux amd64. No se ha construido todavía el caso peatonal, vegetación, hidráulica, energía ni un gemelo 3D completo. Los modelos 3D abiertos de Helsinki son una ruta de expansión documentada, no ejecución acreditada en esta entrega.
