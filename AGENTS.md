# Working on Urban MCP

The research registry is a proposal. Helsinki inventory, Helsinki/Amsterdam walking, historical vegetation, the Bologna/Ingolstadt historical SUMO experiment and the Odense/Utrecht historical SWMM experiment have executable Docker/MCP implementations on main. SUMO and SWMM admission is computational reproduction only, with native model-quality problems and separate host task/prose verdicts preserved. Admit only the operations and cases supported by committed evidence; do not generalize results to the registry, all functions of an engine or entire municipal territories. Keep new code comments, documentation, reports and tasks in English; preserve original source names and historical observed evidence verbatim.

- Preserve the original tool and reuse its supported API/MCP before writing another adapter. The product implementation language is not selected by the Python maintenance utilities.
- A source page is not an admitted dataset. Record exact assets, rights, versions/hashes, area/time, units/CRS, preparation and unresolved inputs.
- Do not infer physical parameters, identities or calibration silently. Synthetic examples must remain distinguishable from real-city evidence.
- Do not promote readiness from a successful metadata check, Docker startup or tools/list alone. Native, MCP and agent evidence are separate milestones.
- Final-product promotion requires the independent third-city gate in `docs/product-qualification.md`: two initial cities, then a person outside the original implementation/test team harvesting and reproducing a third city through native/MCP and both hosts, with an accepted public review. Another agent/model or the author's own run does not count. Keep `registry/product-qualification.json` and the master pending until evidence is accepted; merging into `main` is not final-product qualification.
- Keep credentials, operator datasets, caches, bulk generated outputs and private product code outside Git. Compact reviewed public evidence and manifests belong in the case; larger permitted data snapshots/artifacts go in versioned releases with attribution.
- New skills support the user's existing agent; they do not grant additional permissions, require a provider or override host/user instructions.
- Validate changes with `python tools/validate.py`, `python -m unittest discover -s tests` and the affected case's data preflight. Rebuild generated registries/docs after changing planning TSVs.
- For inventory changes, run its Docker native/MCP suite. For walking changes, run the snapshot integrity regressions and native/MCP suite for both cities. Test all exposed tools and resource/prompt families. Agent testing uses independent workspaces and existing host authentication, with no messaging connectors. A tool script passing is not equivalent to a successful LLM workflow; review both traces and conclusions.
- For vegetation changes, run both city native/MCP suites, categorical/snapshot regressions and original GDAL regressions. Preserve categorical resampling, water/NoData denominators, null population and historical dates. Compare complete paged host responses, source/task hashes and numerical artifacts, then review prose separately; truncated results and water-zone labels do not establish complete evidence or zero land.
- For SUMO changes, follow cases/two-city-sumo/README.md: both city native/XML/TraCI/stdio suites, all thirteen tools/resources/prompt, synthetic contracts and isolated original-method audit. Preserve publisher demand, mandatory signal order, vehicle attributes, processing/seed/time, full scheduled/censored rows, insertion delay and teleport exclusions. Native quality warnings must remain visible; replay does not inherit calibration. Check complete observed comparison/source pages and host artifacts/claims, then review prose and recovered errors separately. Use fresh source-bound workspaces after engine changes.
- Update MASTER_TEST_RECORD.md with the municipal purpose, versions, evidence, failures and limits. Preserve code/data license boundaries; the evaluated unlicensed OSMnx MCP checkout stays outside Git and images. OSM-derived evidence and snapshots retain ODbL-1.0 attribution.
- For SWMM, follow cases/two-city-swmm/README.md. Preserve original hydraulic parameters and all transformations/rights; regional hourly rain and historical models do not establish calibration or forecasts. Test original EPA CLI versus full native report rows/binary observations and actual MCP, all 27 tools/eight resource families/prompt, original tests and lifecycle/interval regressions. Retain original upstream source separately from marked pidfd/balance-lifetime/state-lock changes. Capture native balances after end and before close; do not accept post-close zeros. Advertise binary versus live vocabulary, exact resource URIs and the two-worker budget. Use fresh source/task-bound agent mounts, complete actual pages and separate numeric, task-order and prose verdicts. Preserve initial failed observations and keep final-product qualification pending independent-person third-city review.
